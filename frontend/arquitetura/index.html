01

INTRODUÇÃO

Jogo da velha multiplayer em tempo real

Esta aplicação conecta dois jogadores a uma mesma partida de jogo da velha. Cada usuário pode criar uma conta, entrar no sistema, visualizar quem está online, enviar ou aceitar um convite e jogar com o tabuleiro sincronizado nos dois navegadores.

O servidor centraliza as regras e o estado da partida. Quando um jogador realiza uma ação, o navegador envia um comando; o backend valida a jogada, atualiza os dados e publica o resultado para os clientes conectados. Assim, ambos recebem a mesma versão do tabuleiro, do turno e do placar.

  • 01
    Usuários e presençaCadastro, login, sessão e lista de jogadores online.
  • 02
    Convites e salasEnvio, aceite ou recusa de convites para iniciar uma partida.
  • 03
    Partida sincronizadaTurnos, jogadas, resultados e placar distribuídos em tempo real.
  • 04
    HistóricoConsulta dos resultados das salas finalizadas pelo jogador.

DESTINOS STOMP

Roteamento de mensagens

O QUE É STOMP?

Uma convenção de mensagens sobre o WebSocket

STOMP significa Simple Text Oriented Messaging Protocol. O WebSocket mantém o canal bidirecional aberto; o STOMP organiza as mensagens desse canal em frames e destinos; o JSON transporta os dados da aplicação.

SUBSCRIBE

SEND

MESSAGE

PrefixoPapel realExemplos existentes
/wsEndpoint do handshake e upgrade para WebSocket.ws://localhost:8080/ws
/appEncaminha comandos do cliente para métodos com @MessageMapping./app/users/session, /app/invites/send, /app/rooms/move, /app/history/list
/topicEventos compartilhados com todos os inscritos naquele assunto./topic/users/active, /topic/players/{id}, /topic/rooms/{id}, /topic/ping-pong
/queueFila habilitada no broker; combinada com /user para respostas da sessão atual./user/queue/users

Importante: /user é o destino resolvido pelo Spring para mensagens privadas; o cliente assina /user/queue/users, enquanto o controller usa @SendToUser("/queue/users").

  "data": {
    "roomId": 42,
    "match": {
      "matchId": 9,
      "roomId": 42,
      "playerA": { "id": 1, "login": "ana" },
      "playerB": { "id": 2, "login": "bia" },
      "scoreA": 0,
      "scoreB": 0,
      "status": "ACTIVE",
      "boardId": 7,
      "moves": 1,
      "cells": ["", "", "", "", "X", "", "", "", ""],
      "symbolA": "X",
      "symbolB": "O"
    },
    "nextPlayerId": 2,
    "result": null,
    "winnerPlayerId": null,
    "nextMatch": null
  },
  "error": null
}
Envelope de erro/topic/players/1
{
  "type": "ERROR",
  "data": null,
  "error": "Não é seu turno."
}

O contrato Java é sempre {type, data, error}.

Sessão real/user/queue/users
{
  "type": "LOGGED_IN",
  "data": {
    "id": 1,
    "login": "ana",
    "sessionToken": "<UUID de uso único>"
  },
  "error": null
}

O token expira em 60 segundos e é consumido ao trocar de página/conexão.

07

ORGANIZAÇÃO INTERNA

Camadas do backend

01

Configuração e transporte

WebSocketConfig registra /ws, o broker simples e os prefixos. WebSocketExceptionHandler converte regras inválidas em eventos de erro.

02

Controllers WebSocket

User, Invite, Game, History e ConnectionTest recebem comandos STOMP e escolhem destinos de resposta.

03

Serviços e regras

PresenceService, InviteService, RoomService e PlayerService coordenam os casos de uso; validators protegem invariantes.

04

Mapeamento e contratos

GameMessageMapper transforma entidades em views. Records em GameMessages definem requests, views, estados e o envelope.

05

Persistência

Repositories JPA acessam Player, Invite, Room, Match e Board no H2 em memória.

08

DECISÕES

Tecnologias e justificativas

HTML5 + CSS3

Interface pública, sem etapa de build, com semântica, responsividade e tema por variáveis CSS.

JavaScript

Atualiza telas por eventos e mantém sessão de navegação em sessionStorage.

STOMP.js

Fornece cliente STOMP no navegador e abstrai frames, destinos, inscrições e publicação.

Java 21

Base tipada para domínio, records de mensagens e execução no ecossistema Spring.

Spring Boot 4.1.2

Configuração integrada da aplicação e gerenciamento dos componentes.

Spring WebSocket

Roteamento STOMP declarativo com @MessageMapping, broker simples e mensagens por usuário.

Spring Data JPA + Hibernate

Repositories e transações reduzem código de acesso e preservam o modelo relacional.

H2 em memória

Adequado à demonstração local e reinício limpo; não oferece persistência após encerrar o servidor.

Maven + Lombok

Maven gerencia build/dependências; Lombok reduz código repetitivo de construção e injeção.

09

POSTURA ATUAL

Segurança implementada

Controles presentes no código
  • Operações protegidas verificam o sessionId autenticado.
  • Token UUID de transição, uso único, mantido no servidor e com TTL de 60 s.
  • Identidade da jogada vem da sessão, não do payload do cliente.
  • Validação de participação na sala, turno, índice e ocupação da casa.
  • Mensagens privadas são direcionadas à fila do usuário autenticado.
  • Erros de regra retornam sem expor entidades completas ou stack trace ao cliente.

O H2 Console está habilitado em /h2-console; use jdbc:h2:mem:ticdb enquanto o backend estiver ativo.

Ferramenta externa

Wireshark

Filtrar tcp.port == 8080 para estudar TCP, upgrade e frames.

Checklist de diagnóstico

  1. Confirmar backend na porta 8080.
  2. Verificar resposta 101 Switching Protocols em /ws.
  3. Confirmar frame STOMP CONNECTED.
  4. Validar inscrições antes de publicar comandos.
  5. Comparar o destino e o JSON com os contratos desta página.
  6. Inspecionar ERROR, fechamento do socket e estado no H2.

APRESENTAÇÃO

Roteiro de demonstração

  1. 01

    Preparar dois clientes

    Inicie o backend e abra a aplicação em dois navegadores ou perfis distintos.

  2. 02

    Cadastro e login

    Cadastre dois usuários, autentique ambos e mostre a atualização da lista de online.

  3. 03

    Convite

    Envie um convite, recuse uma vez; envie novamente e aceite para criar a sala.

  4. 04

    Partida sincronizada

    Jogue alternando janelas e destaque o mesmo ROUND_STATE chegando aos dois clientes.

  5. 05

    Regras no servidor

    Mostre que turno incorreto ou casa ocupada gera ERROR sem alterar o tabuleiro.

  6. 06

    Finalização

    Conclua uma rodada, observe a alternância de símbolos, encerre a sala e confira o histórico.

  7. 07

    Comunicação de rede

    Abra os frames WS no DevTools e encerre relacionando WebSocket, STOMP, destinos e payloads JSON observados.
